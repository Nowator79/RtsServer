# RtsServer — состояние проекта

Документ описывает текущее состояние кодовой базы, сильные стороны и недостатки. Обновлён по результатам ревью (февраль 2025).

---

## 1. Текущее состояние

### Технологии и окружение

| Параметр | Значение |
|----------|----------|
| Целевой фреймворк | .NET 10.0 |
| Тип приложения | Консольное, TCP-сервер |
| База данных | MySQL (EF Core, Pomelo) |
| Логирование | Microsoft.Extensions.Logging (консоль) |

### Архитектура в двух словах

- **Точка входа:** `Program.cs` — создаёт логгер, запускает `GameServer`, ждёт Enter, останавливает сервер.
- **Сеть:** `App.NetWork.Tcp` — `Base` (TcpListener, пул клиентов), `Server`, `UserClientTcp` (приём/отправка JSON по строкам).
- **Маршрутизация:** `Router` — словарь action → обработчик (`IProcessor`). Обработчики: авторизация, карты, бой, чат.
- **Игровая логика:** `App.Battle` — `BattleManager`, `Game`, игроки, юниты, постройки, карты, навигация, чат.
- **Данные:** `ApplicationContext` (EF, MySQL) — только для учёток (Login/Regist). Карты/сцены — файловая система. Активные пользователи — in-memory (`DbUsers`).

### Конфигурация

- Порт сервера и строка подключения к БД заданы в коде (нет `appsettings.json`).
- Флаги отладки и поведения — константы в `ConfigGameServer.cs`.

### Что уже исправлено по ревью

- Удалён неиспользуемый импорт `Microsoft.EntityFrameworkCore.Metadata.Internal` из `ChatSystem.cs`.
- Исправлено удаление клиентов при отключении: вместо `ConcurrentBag` используется `ConcurrentDictionary<string, UserClientTcp>`, в `DisconnectUser` вызывается `TryRemove(userClient.Id, out _)`.

---

## 2. Плюсы

- **Разделение по зонам ответственности:** сеть, роутинг, обработчики, бой, БД, адаптеры — границы понятны.
- **Единая точка входа по action:** роутер и регистрация обработчиков упрощают добавление новых команд.
- **Использование async/await** в сетевом коде и циклах обновления.
- **Корректный IDisposable:** флаг `_disposed`, подавление финализации где нужно, аккуратное завершение при остановке.
- **Потокобезопасность пула клиентов:** после правки используется `ConcurrentDictionary` для корректного добавления/удаления клиентов.
- **Логирование** подключено в ключевых местах (сервер, клиенты, батл).
- **Один проект, понятная структура папок** — легко ориентироваться.

## 3. Минусы

### Критичные

| Проблема | Где | Рекомендация |
|----------|-----|--------------|
| Пароли в открытом виде | Login, Regist, UserAuth, БД | Хранить только хэш (BCrypt/Argon2), при логине сравнивать хэш. |
| Строка подключения и чувствительные логи | ApplicationContext | Вынести connection string в конфиг/переменные окружения; отключить `EnableSensitiveDataLogging()` в проде. |
| Риск дедлока при остановке | GameServer.Dispose() | Не вызывать `StopAsync().GetAwaiter().GetResult()` из sync-контекста; предпочтительно явный вызов `StopAsync()` перед выходом. |

### Важные

| Проблема | Где | Рекомендация |
|----------|-----|--------------|
| Нет проверки индексов/ключей | GetInfoUnitHandler и др. | Перед обращением к словарям/спискам проверять наличие ключа; при невалидных данных возвращать ошибку клиенту. |
| MainProcessor.GameServer без защиты от null | MainProcessor.Handler | Задавать контекст в конструкторе или проверять на null и бросать понятное исключение. |
| Устаревший SendMessage() | Login, GetInfoUnitHandler, чат и др. | Перейти на SendAsync() с обработкой ошибок. |
| Логирование через Console | Router | Использовать ILogger вместо Console.WriteLine. |

### Средние

| Проблема | Где | Рекомендация |
|----------|-----|--------------|
| Несколько своих LoggerFactory | Program, GameServer, BattleManager, UserClientTcp | Один раз настроить логгер и передавать ILogger в конструкторы (или DI). |
| Переданный CancellationToken не используется | GameServer | Либо связать с внутренним CancellationTokenSource, либо не передавать из Program. |
| Вся конфигурация в коде | Program, ApplicationContext, ConfigGameServer | Вынести порт, БД, флаги в appsettings.json или переменные окружения. |

### Низкие / стиль

| Проблема | Где | Рекомендация |
|----------|-----|--------------|
| Соответствие action и процессора | Router: `/gameBattle/unitSetTarget/attack/` → BuildConstructionProcessor | Убедиться, что это задумано (атака vs строительство). |
| Много предупреждений компилятора | По проекту | Постепенно править nullable, недостижимый код, устаревшие методы. |
| Трафик без шифрования | TCP | Для продакшена рассмотреть TLS (SslStream) или отдельный канал для аутентификации (HTTPS). |

## 4. Краткий итог

Проект в рабочем состоянии, структура понятная, после правок корректно обрабатывается отключение клиентов. Главные риски — безопасность (пароли, конфиг, логи) и устойчивость к невалидным запросам. Рекомендуется вынести конфигурацию и пароли в безопасный конфиг и перейти на хэширование паролей перед дальнейшим развитием.
